# SEO 修复优先级工作流

**工具定位：分析你已提供的数据，产出可复核的 SEO 问题分流报告。** 输入规范化的抓取观察记录与业务背景后，脚本分析这些输入，再由 agent／编辑整理交付说明。工具不内置网站爬虫、Search Console 连接，也不会独立验证输入观察是否真实。

报告是否有用，取决于输入数据的质量、完整性和覆盖范围。缺失证据必须明确保留；输出是供人工判断的建议，不等于页面必须修改或线上故障已经证实。这个仓库用于作品集展示分析判断与报告交付能力，并非 Huiyang 的主要生产工作流。

**日常／客户项目用法：** 客户已提供获准使用的抓取导出表和页面／业务背景时，可用它辅助整理优先级复核报告与开发交付说明。 使用前先映射为约定的数据格式，核对来源与缺失字段，向客户交付前仍需人工审阅。作品集展示不是唯一用途；这也不表示它已成为经过完整验证的生产服务，或替新增内容选定了许可。

## 解决什么问题

把用户提供的抓取导出片段与业务背景，整理为开发、SEO 和内容团队可以审阅的修复／调查队列。适用于迁移后的修复排期、获客落地页检查、或先筛选大量抓取警告再交给工程团队。不会仅凭抓取记录解释排名下降原因。

输入：按[数据契约](INPUT-CONTRACT.md)明确映射的 JSON、来源及行号、观察日期、页面是否计划参与自然搜索、业务重要性、目标及可选负责人／工作量。

输出：八类有限检查的候选队列，含优先级、分数组成、证据可信度、必须先调查的条件、负责人、修复建议、验收检查、排除项与未评估字段。配合技能还会产出便于交接的人工审阅报告。

## 如何运行

需要 Python 3.10+，仅使用标准库，不需要付费 API。

```sh
python scripts/triage.py cases/fictional-harbor/input.v1.json > /tmp/seo-first-output.json
python -m unittest discover -s tests -v
```

Agent 使用前先阅读 [SKILL.md](skills/seo-fix-priority-workflow/SKILL.md)。不会自动猜 CSV 列名；必须保留原始数据并记录映射。队列只是建议，不授权修改网站。

## 改编贡献

保留上游“提供数据→业务背景→影响与工作量评分→可执行交付”的核心流程及 40/40/20 公式。将十类全面审计缩小为 HTTP 错误、不可索引标记、robots 阻挡标记、canonical 差异、多跳转、缺失标题、页面深度、零入链八类证据信号。

新增页面意图、证据来源与日期、可信度、缺失信息、负责人、验收标准和优先于分数的调查门槛。删除实时抓取／付费 API 路径、自动猜平台、全站健康分数和不具备的 XLSX 交付承诺。[改编映射](ADAPTATION.md)说明了继承、改写及删除的具体位置。

## 案例与边界

[Harbor 虚构案例](cases/fictional-harbor/)包含原始证据、背景、输入映射、Agent 实际运行的首版输出、复核及交接。案例是离线虚构演练，不是真实客户项目、线上网站审计、独立人工评审或 SEO 成效证明。

测试验证决策逻辑、严格数据类型、证据追踪、不确定性处理、输出契约和上游文件校验，不证明流量或排名提升。旧版两条规则、三行数据的演示保留在 [legacy/v0.1](legacy/v0.1/)及原示例路径，不作为新版验证。

不抓取 URL，不调用付费服务，不使用客户数据，不检查实时索引、渲染页面、Core Web Vitals、完整站点地图、重复内容，也不部署修复。canonical 差异可能合理；局部抓取里的零入链不能证明孤立页面；404 可能是有意下线。30 天证据时效、深度与优先级阈值都是本项目规则。缺失字段代表未评估；高可信度仅表示对所提供信号分类的把握，不验证数据真实性、线上缺陷或排名收益。相关症状需在排期前合并判断，不能重复计算收益。
